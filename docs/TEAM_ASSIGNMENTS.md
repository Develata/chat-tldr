## 2. 已经拍板的规则

- 以 [CLI_PROTOCOL](CLI_PROTOCOL.md) 和 [DATA_MODEL](DATA_MODEL.md) 为共享接口；[CLI_V1_REVIEW](CLI_V1_REVIEW.md) 是已采纳的首次 v1 调整记录。
- 不做脱敏。分析时聊天文本会发送给 Jev 与默认 DeepSeek；图片不上传。主线离线测试不调用云服务。
- 除 TopicSummary 外，任何有截止日期的结论都属于 P0，哪怕负责人是其他人；保留实际负责人，不改写为“我”。
- GUI/eval 只依赖 core，通过 CLI 子进程读 JSONL；数据库只由 engine 打开。
- 文件归属、私有数据、缓存与输出目录按 [FILE_LAYOUT](FILE_LAYOUT.md)。API key 只来自环境变量，真实聊天、数据库、原始导出不能提交。
- QCE 为 GPL-3.0，本项目为 MIT：不复制或链接 QCE 代码。管理组件是否分发上游程序、如何提供其许可/源码信息须单独明确；本轮不捆绑分发。

## 3. 各任务怎么开始

### A：QCE 管理组件

2026-09-27 由 Codex 接手。本轮实现范围为本机 QCE/NapCat 状态、扫码登录、完整 JSON 导出和受控清理，使用说明见 [组件 README](../apps/qce-manager/README.md)。不安装 QCE、不启动/停止容器、不纳入发布包；跨平台 CI 与真实联调分开报告，旧 Docker 导出记录不替代新组件验收。

最低交付是可重复执行的导出流程和文件路径；随后再封装 Rust 程序。主线提供 `chat-tldr import <绝对路径>`，成功 `ack.detail.chat_ids` 可用于选群。输入仍归管理组件/用户所有，导入不移动、不删除。

验收：正常导出、未登录/启动失败、写到一半失败、文件名含空格、重复导出；清理只作用于自己的下载缓存和已结束任务临时目录，不碰原始导出、数据库或活跃任务。不提供任意路径递归删除功能。

### B：GUI 设计

先运行现有 [GUI](../apps/gui/README.md)，在 `docs/ui/` 补交设计复核和可查看的线框图，覆盖：空数据、选群/导入、分析中、P0–P3 收件箱、展开证据、部分失败、没有安全已读边界、事项完成/忽略/恢复，以及六个分析总览的入口与窗口切换。

设计复用 `fixtures/jsonl/inbox.jsonl` 和 [多场景样本](../fixtures/qce/scenario-analysis.README.md)。总览提供近 6/24 小时与近 7 天窗口，但优先事项保留窗口前的未完成 P0。总览不授予标已读权限；收件箱也只有完整成功且全部结论已展示时才可标读。未实现命令由 `version.capabilities` 判定；首次分析提示实际云服务去向。

验收：每个按钮对应 CLI 命令；证据可以回到原文；P0、负责人和截止时间可辨；长中文、无截止时间、空列表、错误信息都能显示。暂不要求完整 GUI 代码。

### C：合成数据与交付验收

先按 EVALUATION §5 独立标注真实 200 条 CSV，第二位同学独立标预先随机固定的 50 条，可阅读全量上下文。两人的工作目录只含原始材料，不附模型预测；保留独立版本和分歧记录，人工裁决后再形成完整 gold。字段 thread/todo/announcement/items_json 均需明确填写；源文本列的 `text:` 前缀保留。不得读取模型结果后照抄 gold，不得用 LLM 自动生成真实 gold。CSV 和源聊天留在 private/，用 `import-sheet --messages <协调者保管的原始流>` 核对源列、消息范围和标签格式后再交付；第二人未填完整的工作表不能直接导入。未完成前真实质量和校准曲线写“待标注”。

合成补充参考 [100 条主样本与 4 条回填样本](../fixtures/qce/scenario-analysis.README.md)，先看原文写独立期望，重点覆盖 @全体、同名不同身份、他人截止 P0、更正/取消、部分回答与回填。

独立合成 gold 放 `eval/synthetic/<场景名>/`；真实标注只在 private/。新增合成输入交付 group.json 与 README；复用样本只写路径/消息 ID，不复制权威来源。score 支持 Ours/B0 与话题指标，calibrate 用法见 [eval/README](../eval/README.md)。

纯人工写作或程序合成；不要把真实聊天换昵称后当成合成材料。正式 gold 格式按 [EVALUATION](EVALUATION.md)；评估器未实现的字段先在 README 记录期望，不造一个不兼容格式。

验收报告放 `reports/<日期>/`，写明 Git 提交、命令、预期、实际和复现步骤。真实群样本只在 `eval/private/`，由 Develata 安排取得同意与运行；未经实测的指标保持空缺。
