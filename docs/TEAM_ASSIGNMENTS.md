## 2. 已经拍板的规则

- 以 [CLI_PROTOCOL](CLI_PROTOCOL.md) 和 [DATA_MODEL](DATA_MODEL.md) 为共享接口；[CLI_V1_REVIEW](CLI_V1_REVIEW.md) 是已采纳的首次 v1 调整记录。
- 不做脱敏。分析时聊天文本会发送给 Jev 与默认 DeepSeek；图片不上传。主线离线测试不调用云服务。
- 除 TopicSummary 外，任何有截止日期的结论都属于 P0，哪怕负责人是其他人；保留实际负责人，不改写为“我”。
- GUI/eval 只依赖 core，通过 CLI 子进程读 JSONL；数据库只由 engine 打开。
- 文件归属、私有数据、缓存与输出目录按 [FILE_LAYOUT](FILE_LAYOUT.md)。API key 只来自环境变量，真实聊天、数据库、原始导出不能提交。
- QCE 为 GPL-3.0，本项目为 MIT：不复制或链接 QCE 代码。管理组件是否分发上游程序、如何提供其许可/源码信息须单独明确；本轮不捆绑分发。

## 3. 各任务怎么开始

### A：QCE 管理组件

先提交 `apps/qce-manager/` 内的接入说明：目标 QCE 版本、支持平台、获取来源、启动/停止方式、导出动作、成功/失败的返回值。具体上游 API 以实际核对为准，不能假定已有 HTTP 接口。

最低交付是可重复执行的导出流程和文件路径；随后再封装 Rust 程序。主线提供 `chat-tldr import <绝对路径>`，成功 `ack.detail.chat_ids` 可用于选群。输入仍归管理组件/用户所有，导入不移动、不删除。

验收：正常导出、未登录/启动失败、写到一半失败、文件名含空格、重复导出；清理只作用于自己的下载缓存和已结束任务临时目录，不碰原始导出、数据库或活跃任务。不提供任意路径递归删除功能。

### B：GUI 设计

先交一份 `docs/ui/README.md` 和可查看的线框图，覆盖：空数据、选群/导入、分析中、P0–P3 收件箱、展开证据、部分失败、没有安全已读边界、事项完成/忽略/恢复。

设计直接复用 `fixtures/jsonl/inbox.jsonl` 等样例。`view_cursor=null` 时禁用“标为已读”；部分失败后刷新 inbox；未实现命令由 `version` 的 capabilities 判定，不能把占位按钮当作已可调用能力。首次分析提示实际云服务去向。

验收：每个按钮对应 CLI 命令；证据可以回到原文；P0、负责人和截止时间可辨；长中文、无截止时间、空列表、错误信息都能显示。暂不要求完整 GUI 代码。

### C：合成数据与交付验收

先做 3–5 个短场景，放 `eval/synthetic/<场景名>/`，各有 `group.json` 和 `README.md`。至少覆盖 @全体成员、由别人负责但有截止日期的 P0、同时间消息/悬空回复、无明确日期的普通讨论。期望结果逐条引用原消息，避免只给主观总结。

纯人工写作或程序合成；不要把真实聊天换昵称后当成合成材料。正式 gold 格式按 [EVALUATION](EVALUATION.md)；评估器未实现的字段先在 README 记录期望，不造一个不兼容格式。

验收报告放 `reports/<日期>/`，写明 Git 提交、命令、预期、实际和复现步骤。真实群样本只在 `eval/private/`，由 Develata 安排取得同意与运行；未经实测的指标保持空缺。

## 4. 主线执行顺序

| 顺序 | 交付与退出条件 |
|---|---|
| 第一批：共用基础 | 六成员 workspace、core 类型/流校验、合成 QCE/JSONL、配置模板、离线 CLI 导入/查询、SQLite 初始迁移、`fmt`/`clippy`/`test` CI；合并 main 后同学即可接入 |
| 第二批：完整分析 | render/temporal/verify、模型 mock 与真实客户端、控制器检查点、分析/收件箱/反馈/已读命令；先通过 mock，再由 Develata 提供私有样本实测 |
| 第三批：交付闭环 | GUI/HTML、评估与演示脚本、失败恢复验收、真实导出兼容确认；以剩余时间决定外围功能 |

不要把“源码已建目录”“fixture 可解析”写成真实分析/GUI/指标已完成。当前实际支持的命令以 `cargo run -p chat-tldr -- version` 为准。

## 5. Git 与交接

本次初始化沿用 `docs/initial-spec`，由 Codex 完成检查、PR、合并并同步 main，已经获得 Develata 授权。后续同学从最新 main 开任务分支，例如 `a/qce-manager`、`b/gui-design`、`c/synthetic-cases`，仅提交自己的目录，由 Develata 合并。

每次交接写四项：变更文件、怎么运行、实际检查结果、仍未实现或需要确认的地方。源码 PR 运行 fmt/clippy/test；文档与设计 PR 校验链接/样例并遵循同一 CI。不要变更冻结公共接口来绕过集成问题。

`.github/CODEOWNERS` 当前真实审核人只有 `@Develata`；收到同学账号后再加对应路径。CODEOWNERS 是审核路由，不是文件写入权限控制。分支保护与“同学是否能自行合并”应分别验证。
