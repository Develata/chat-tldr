# ADR-0004 混合式话题切分，embedding 可选

**背景**：群聊中多个话题交织进行。“好的”“+1”这类短消息单独做语义向量没有意义。3 天内无法训练切分模型。

**决策**：三层切分。
1. 确定性 burst：时间间隔、回复边、@ 边、同一发送者连续发言。
2. 候选话题：默认把**全部**活跃话题作为候选；只有活跃话题数超过硬阈值（`all_candidates_max`），或估算 token 超过 Jev 预算（`state_token_budget`）时，才用 `α·cos + β·连边 − γ·时间衰减` 取 top-K。embedding 可选，未配置时 α = 0。
3. Jev 在候选 + `new_topic` 中做归属判断，按 `confidence` 分三档：直接归入、LLM 复核、新开话题。

**理由**
- 回复和 @ 是最可靠的信号，规则就能处理大部分情况，而且零成本、可解释。
- 群聊中活跃话题通常少于 20 个，Jev 的 choice 最多支持 255 个选项，全量候选可以避免 embedding 粗筛漏掉正确话题，还省掉一个依赖和一个外部服务。
- Jev 返回概率分布和 confidence，适合做“有把握就直接归入，没把握再交给 LLM”的分档。
- 评估以 disentanglement 指标为主（1-to-1、exact-match F1），而不是线性边界指标，因为交织话题没有明确定义的线性边界。

**代价**
- 话题归属依赖 Jev 的中文能力（官方说明中文精度低于英文）。缓解：记录全部概率做校准评估，阈值用标注数据调，保留 LlmDecider 降级路径和 Sim-TFIDF 对照。
- 在线聚类与顺序有关：消息处理顺序不同，结果可能不同。缓解：按 `(sent_at, ordinal)` 全序处理，回填消息按其发送时刻取候选。
