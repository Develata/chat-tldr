# ADR-0006 证据校验不变量：LLM 提出，Rust 验证

**背景**：本项目与“把聊天记录丢给 LLM 总结”的核心区别是可追溯。LLM 会编造引用。

**决策**
- 每条 Insight 必须带证据（`message_id` + `quote`）。
- Rust 校验：消息存在且未撤回；quote 是渲染文本的子串（只忽略空白差异，不做模糊匹配）；截止日期原文出现在证据消息中。
- 校验的对象是 `render(message, render_profile)`，即**模型实际看到的文本**（经过占位、转发展开），而不是原始文本。`render_profile` 记录在每条证据上，也进入缓存键。
- 高风险类型（MentionMe、Todo、Announcement、Decision、任何带截止日期的结论）不通过就重试一次，仍不通过就 `rejected`，不进收件箱，但计入统计并展示。只有 TopicSummary 允许 `unverified`。

**理由**
- 精确子串匹配可以由程序判断，没有灰色地带；模糊匹配会重新引入“相信模型”。
- 模型看到的是渲染后的文本（`[图片]`、展开的转发），对渲染视图校验才与模型的输入一致；渲染规则变化时 `render_profile` 版本随之变化，旧证据仍可按原版本复核。
- 被拒数量公开展示，让用户知道系统丢掉了什么，而不是悄悄过滤。

**代价**
- 模型复述时改动标点或用词会导致误拒。缓解：提示词要求“逐字复制原文片段”，用短引用 `n1` 代替长 ID，失败时把原因反馈给模型重试一次。
- 显示时需要计算高亮位置，这由 CLI 负责（`EvidenceView.highlight`），GUI 不做匹配。
