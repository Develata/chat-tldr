# ADR-0010 更正、取消与问答关系（已确认）

用户要求这些能力完成后才能打第一个 tag。首版不添加新推荐视图，关系数据由 engine 产生和验证，CLI 提供可追溯结果。

2026-09-26，Develata 确认采用独立关系表与查询，允许下述 SQLite v1→v2 加法迁移。

## 已采用的契约

- 扩展内部 LLM 抽取 DTO，同一次话题抽取可提出 `replaces`、`cancels`、`conflicts`、`question`、`answers` 关系。答案区分完整和部分；普通回复、确认收到不能自动算作回答。
- 每条关系保存源消息，关联关系再保存目标消息，以及各自逐字引用。两端必须来自同群、同次已提供的上下文；更正/回答不能早于原消息。Rust 重新验证引用、撤回和时间关系；引用有效不等于已获人工语义确认。
- 问题状态由已验证关系按消息顺序归纳，完整回答关闭待回应标记，部分回答保留待回应。历史回填不能凭导入时间覆盖更晚状态；Closed 话题仍保持关闭。
- 使用独立 SQLite 表保存关系，与话题检查点原子提交；合并话题时迁移归属。数据库从 v1 加法迁移到 v2，保留已有消息、结论、反馈、游标。查询不触发迁移；写入时事务迁移。旧数据缺少关系分析时明确报告覆盖缺口，不能当作没有问题。
- 新增只读 `relations --chat <ID> [--since <RFC3339>] [--until <RFC3339>]`，返回 `ack` 头部和逐行关系/问题；沿用 JSONL 外层 schema 1.0 和已有错误/结束事件。窗口截至 `until`，不会用未来回答解决过去的问题。
- 旧/新安排及取消关系并列显示，保留双方证据。模型不修改用户 done/dismissed；也不删除旧结论或静默替换其证据。冲突不是已经解决的变更。
- 冻结的 UnifiedMessage、Insight、CliEvent、AgentAction 不改字段；新关系是独立类型。GUI 的新关系界面与打包后续补齐，本轮交付 CLI 查询。

## 验收条件

合成反例覆盖：延期与取消、同名不同事项、相互冲突但未定案、直接回答/间接回答/部分回答、只有 reply 但没有回答、重复导入、旧消息回填、撤回、未来信息、无法验证的引用、提示词注入，以及 v1 数据迁移后原数据与游标不变。

真实语义质量仍待人工标注；不把合成测试或引用校验描述成真实识别准确率。
